## 0. 先回答昨天的悬念

```swift
let stocks = ["T恤": 5]
print(stocks["T恤"])    // Optional(5),不是 5
```

字典里**可能没有**这个 key。Python 的 `d["鞋"]` 会抛 `KeyError`,`d.get("鞋")` 返回 `None`。
Swift 的做法:取值**一律**返回 `Int?`,你必须处理「没有」的情况,否则编译不过。

> Python 是「运行到才崩」,Swift 是「编译时就逼你处理」。

---

## 1. Optional 是什么

`Int` 一定有值;`Int?` 表示「**要么是一个 Int,要么是 nil**」。

```swift
var maybeStock: Int? = nil     // 现在没有值
maybeStock = 3                 // 现在有值
var z: Int = nil               // ❌ 普通 Int 不能是 nil
```

`nil` 相当于 Python 的 `None`,但区别很大:Python 里任何变量都可能是 `None`,Swift 里**只有**带 `?` 的类型才可能是 `nil`。

不处理就用,编译错误:

```swift
let x: Int? = 5
let y = x + 1      // ❌ value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

报错的意思:`Int?` 是个「盒子」,要先**解包(unwrap)**拿出里面的 `Int` 才能算。

---

## 2. 四种解包方式

| Swift | 意思 | 接近的 Python |
|---|---|---|
| `x ?? 0` | nil 就用默认值 0 | `x if x is not None else 0` |
| `if let v = x { }` | 有值才执行 | `if x is not None:` |
| `guard let v = x else { return }` | 没值就提前退出 | `if x is None: return` |
| `x!` | 强制解包,nil 就**崩溃** | 直接用,运行时报错 |

### 2.1 `??`(空合并运算符)

```swift
let s = stocks["鞋"] ?? 0     // 没有就当 0
```

最简洁。适合「缺了有合理默认值」的场合。

### 2.2 `if let`

```swift
if let n = stocks["帽子"] {
    print("帽子库存 \(n)")     // 这里 n 是 Int,不是 Int?
} else {
    print("没有这个商品")
}
```

`n` 只在花括号里有效。

### 2.3 `guard let`

```swift
func describe(_ stock: Int?) -> String {
    guard let stock else { return "未知" }   // nil 就提前返回
    if stock == 0 { return "售罄" }
    return "剩 \(stock) 件"                  // 之后 stock 都是 Int
}
```

和 `if let` 的区别:`guard let` 解包出来的变量在**整个函数后面**都能用,代码不会越嵌越深。「先排除异常情况,再写正常流程」。

> `guard let stock else` 是 Swift 5.7+ 的简写,等价于 `guard let stock = stock else`。

### 2.4 `!` 强制解包(能不用就不用)

```swift
let sure = stocks["T恤"]!     // 确定有值才行
let boom = stocks["鞋"]!      // 💥 运行时崩溃:Unexpectedly found nil
```

App 里崩溃 = 用户看到闪退。除非你 100% 确定,否则别用。

## 3. 可选链 `?.`

```swift
let name: String? = "T恤"
name?.count            // Optional(2)
let none: String? = nil
none?.count            // nil,不崩溃
none?.count ?? 0       // 0
```

链中任何一环是 `nil`,整条链就是 `nil`。类似 Python 的 `x.count if x is not None else None`。

---

## 4. 怎么选?

| 场景 | 用什么 |
|---|---|
| 缺了有合理默认值(观众数缺了显示 0) | `??` |
| 有值才做某件事 | `if let` |
| 缺了就没法继续(函数里必需的参数) | `guard let` |
| 100% 确定有值 | 尽量不用 `!` |

项目里的真实例子(`Models.swift` 的 `LiveEvent.decode`):

```swift
case "viewers": return .viewers(r.count ?? 0)                       // 缺了就当 0
case "host_audio":
    guard let id = r.id, let url = r.audioUrl else { return nil }   // 缺一个,整条丢掉
```

为什么两处处理不同:观众数缺了显示 0 无伤大雅;音声缺 id 就没法和文字对上,缺 url 就没东西可播,宁可不处理。

## 7. 日语术语(面试用)

| 中文 | 日语 | 英文 |
|---|---|---|
| 可选类型 | オプショナル型(がた) | Optional |
| 解包 | アンラップ | unwrap |
| 强制解包 | 強制アンラップ(きょうせい) | force unwrap |
| 可选绑定 | オプショナルバインディング | optional binding(`if let`) |
| 空合并运算符 | nil合体演算子(ごうたいえんざんし) | nil-coalescing operator |
| 可选链 | オプショナルチェーン | optional chaining |
| 提前退出 | 早期リターン(そうき) | early return(`guard`) |
| 空值 | ヌル / nil | nil |
| 崩溃 | クラッシュ | crash |

**面试式说法(试着读出来):**

- 「Swift のオプショナル型は、値が存在しない可能性を型で表現する仕組みです。」
  (Swift 的 Optional 是用类型表达「值可能不存在」的机制。)
- 「`if let` でオプショナルバインディングを行い、安全にアンラップします。」
  (用 `if let` 做可选绑定,安全地解包。)
- 「強制アンラップは nil の場合にクラッシュするため、できるだけ避けて、`guard let` や `??` を使います。」
  (强制解包遇到 nil 会崩溃,所以尽量避免,改用 `guard let` 或 `??`。)
