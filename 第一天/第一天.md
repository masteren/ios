## 0. 先搞清楚一件事:Swift 和 Python 最大的区别

| | Python | Swift |
|---|---|---|
| 运行方式 | 解释器逐行执行,运行到才发现错 | **先编译**,类型不对根本不让你运行 |
| 变量的类型 | 随时可以变:`x = 1` 之后 `x = "a"` 没问题 | 定下来就不能变 |
| 缩进 | 缩进是语法 | 缩进只是好看,用 `{ }` 分块 |
| 行尾 | 无 | 不需要分号 |

最重要的是第二行:**Swift 会在你运行之前就把一大类错误拦下来**。一开始你会觉得它「很烦」,但这正是 iOS App 稳定的原因。今天会故意写错几次,让你习惯读报错。

## 2. `let` 和 `var`

```swift
let name = "T恤"      // let:赋值后不能再改(常量)
var stock = 5          // var:可以改(变量)
stock = 4              // ✅
name = "帽子"           // ❌ 编译错误
```

**Python 没有 `let`**——Python 里所有变量都可以随便重新赋值。

**原则:默认用 `let`,确实需要改的时候才换成 `var`。** 好处是你一眼就能看出「这个值后面不会变」,代码更好读,也更少出错。Xcode 还会提示你「这个 `var` 从来没被修改过,改成 `let` 吧」。

## 3. 类型与类型推断

Swift 每个值都有明确的类型。今天只需要认识 4 个:

| 类型 | 例子 | 对应的 Python |
|---|---|---|
| `Int` | `3000`、`-5` | `int` |
| `Double` | `0.8`、`3.14` | `float` |
| `String` | `"T恤"` | `str` |
| `Bool` | `true`、`false`(**小写**) | `bool`(`True` / `False`,首字母大写) |

你不用每次都写类型,编译器会自己判断,这叫**类型推断**:

```swift
let price = 3000          // 编译器推断:Int
let rate = 0.1            // 推断:Double
let isActive = true       // 推断:Bool
let title = "夏季新品"     // 推断:String
```

也可以显式写出来,效果完全一样:

```swift
let price: Int = 3000
let discount: Double = 0.8
```

什么时候要显式写?当编译器猜不出来,或者你想要别的类型的时候,比如 `let x: Double = 3`(不写的话 `3` 会被当成 `Int`)。

### ⚠️ Int 和 Double 不能直接混着算

Python 里 `3000 * 0.8` 没问题,Swift 里**报错**:

```swift
let price = 3000
let rate = 0.1
let total = price * rate    // ❌ 'Int' 和 'Double' 不能相乘
```

必须手动转换:

```swift
let total = Double(price) * rate    // ✅ 把 price 转成 Double
let rounded = Int(total)            // ✅ Double → Int(直接去掉小数,不是四舍五入)
```

这是 Python 转 Swift 时最常见的第一个坑。

## 4. 字符串插值

| Python | Swift |
|---|---|
| `f"{name} 库存 {stock}"` | `"\(name) 库存 \(stock)"` |

Swift 用 `\( )` 把变量嵌进字符串里,括号里还可以写表达式:`"合计 \(price * 2) 日元"`。

## 5. 数组和字典

| Python | Swift |
|---|---|
| `names = ["T恤", "帽子"]` | `var names = ["T恤", "帽子"]` |
| `list[str]` | `[String]` |
| `names.append("包")` | `names.append("包")` |
| `len(names)` | `names.count` |
| `names[0]` | `names[0]` |
| `stocks = {"T恤": 5}` | `var stocks = ["T恤": 5]` |
| `dict[str, int]` | `[String: Int]` |

两个要注意的点:

1. **数组里的元素类型必须一致**。`["T恤", 5]` 不行(Python 可以)。
2. 注意上面都写了 `var`:`let` 的数组**不能** `append`,因为数组本身是常量。

字典取值有一个今天先留个悬念的细节:

```swift
let stocks = ["T恤": 5]
print(stocks["T恤"])    // 打印出 Optional(5),而不是 5
```

为什么是 `Optional(5)`?因为字典里**可能没有这个 key**,Swift 用 `Optional` 表示「可能有、可能没有」。这是**明天**的内容,今天看到记住「这是正常的」就行。

## 7. 读报错:今天最重要的练习

打开 `day1.swift`,在最底部取消注释这三行,**一次取消一行**,运行并读报错:

```swift
name = "帽子"
stock = "五"
let total = price * rate
```

你会看到(真实输出):

```text
error: cannot assign to value: 'name' is a 'let' constant
error: cannot assign value of type 'String' to type 'Int'
error: binary operator '*' cannot be applied to operands of type 'Int' and 'Double'
```

翻译一下:

| 报错 | 意思 |
|---|---|
| `'name' is a 'let' constant` | `name` 是用 `let` 声明的,不能改 → 要改就把 `let` 换成 `var` |
| `cannot assign value of type 'String' to type 'Int'` | 想把字符串塞进 `Int` 变量 → 类型不对 |
| `'*' cannot be applied to 'Int' and 'Double'` | 整数和小数不能直接乘 → 手动转换 |

**读报错的方法**:先看 `error:` 后面那句话,再看它指向的文件和行号。Swift 的报错信息通常写得很清楚,比 Python 的 traceback 友好。

## 9. 自测问题

1. `let` 和 `var` 的区别是什么?什么时候用哪个?
2. `let a = 5` 之后,能写 `a = 6` 吗?能写 `a = "六"` 吗?为什么?
3. `let x = 3000 * 0.8` 能编译吗?`let p = 3000`、`let x = p * 0.8` 呢?为什么两者不一样?(提示:字面量 `0.8` 和 `3000` 可以自动适应,变量 `p` 已经定了类型。)
4. Swift 的 `Bool` 值怎么写?
5. `let list = [1, 2, 3]` 之后,能 `list.append(4)` 吗?

<details>
<summary>答案要点</summary>

1. `let` 赋值后不能改,`var` 可以改。默认用 `let`,需要改才用 `var`。
2. 都不能。第一个违反 `let`;第二个类型错了,而且也违反 `let`。
3. 第一个能:两个都是字面量,编译器会把 `3000` 当作 `Double` 处理,结果是 `2400.0`;第二个不能,因为 `p` 已经是 `Int` 了。(这点是个细节,觉得绕可以跳过,记住「变量之间别混着算」即可。)
4. `true` / `false`,全小写。
5. 不能,`list` 是 `let`,数组被锁定了。要追加得改成 `var`。

## 10. 日语术语(面试用)

| 中文 | 日语 | 英文 |

**面试式说法(试着读出来):**

- 「`let` は定数を宣言するキーワードで、一度代入したら変更できません。変更が必要な場合は `var` を使います。」
  (`let` 是声明常量的关键字,赋值后不能改;需要改时用 `var`。)
- 「Swift は型推論があるので、型を明示しなくてもコンパイラが自動で判断してくれます。」
  (Swift 有类型推断,不写类型编译器也会自动判断。)
- 「Swift は静的型付け言語なので、型が合わないとコンパイルエラーになります。」
  (Swift 是静态类型语言,类型不匹配会编译报错。)
