# 学习笔记 16:按「场景」找 bug(iOS)

正常流程(注册 → 弹幕 → 下单)早就有测试了。这次专门想「不正常的用法」,每个场景写成一个自动测试(`ios/AILiveCommerceUITests/EdgeCaseUITests.swift`)。

## 想了哪些场景,结果如何
| 场景 | 结果 |
|---|---|
| 登录用不存在的用户、注册时密码太短 | **发现 bug**:密码太短时显示英文 `String should have at least 6 characters` |
| 加进购物车之后,库存被别人买光 | 没问题:下单时提示「在庫が不足しています」,购物车保留,直播页按钮变灰显示「在庫切れ」 |
| 连续快速发弹幕(超过 10 秒 5 条) | **发现 2 个小问题**:① 用键盘的发送键发一条后键盘就收起来,没法连续发 ② 同一句提示连续出现时,提示会提前消失 |
| 服务器地址乱填(`not a url`、`ftp://…`、空主机) | 没问题:不崩溃,只是连不上 |
| 手机设成深色模式、把系统字体调到最大 | **发现 bug**:最大字体时直播页内容超出屏幕左右、价格被折成两行 |
| 使用中服务器挂掉,过一会儿恢复 | 没问题:显示「接続しています…」,发不出去的弹幕留在输入框,服务器恢复后自动重连并能发送 |
| (顺带发现)商品卖光后 | **发现 bug**:主播的自动播报还在推荐已经卖光的商品(「本日は38%オフ…」) |

## 怎么修的
- **英文报错**:根源在服务器。FastAPI 对输入检查失败默认返回英文 + 内部字段名的数组。在 `app/main.py` 加了一个 `RequestValidationError` 的处理函数,统一返回一句日文(「パスワードは6〜64文字で入力してください」)。**网页版也有同样的问题,这样一次都修好了**——修在源头比在每个客户端各修一遍好。
- **最大字体**:`AILiveCommerceApp.swift` 里用 `.dynamicTypeSize(...DynamicTypeSize.xxLarge)` 设了上限;价格行加 `lineLimit(1)` + `minimumScaleFactor`(放不下时缩小字,而不是折行)。
- **深色模式**:画面只设计了浅色,所以用 `.preferredColorScheme(.light)` 固定成浅色。
- **键盘收起**:发送后把焦点放回输入框(`LiveView.swift` 的 `send()`)。
- **提示提前消失**:原来的写法是「2.5 秒后,如果现在显示的还是这句话就清掉」。同一句话连出两次时,第一次的计时器会把第二次的也清掉。改成用序号判断「我是不是最后一次」(`AppState.showToast`)。
- **卖光还推荐**:`app/ai_host.py` 的 `_idle_line` 只从有库存的商品里选。

## 写测试时学到的
- **从 App 外面制造状况**:测试里直接调管理 API 把库存改成 0(模拟「别人先买走了」);另开一个脚本在测试中途杀掉并重启服务器。
- **一闪而过的东西很难测**:提示只显示 2.5 秒,测试稍慢一点就错过了。要在「刚触发之后马上」去检查。
- **测试失败 ≠ App 有 bug**:这次有好几次失败是测试自己的问题(点得太快、键盘挡住了标签栏、要检查的文字在打字时本来就是隐藏的)。先看失败时的截图和界面结构,再判断是哪边的问题。

## 「登录后第一次点标签栏没反应」的调查
自动测试里,登录弹窗关闭后第一次点底部标签不切换,第二次才行。一开始以为是点得太快。
- 做法:写了一个探测用的测试,登录后分别等 0 / 0.5 / 1 / 2 / 3.5 秒再点**一次**,记录是否切换。
- 结果:等 3.5 秒也不切换 → **不是时间问题,是有东西挡着**。
- 再截图:画面上是 iOS 系统的「保存密码?」对话框。第一次点击只是把它关掉了。
- 结论:**不是 App 的 bug**,是系统功能(登录成功后询问是否把密码存进钥匙串)。因为登录表单正确标注了「这是用户名/这是密码」,系统才会问。
- 教训:猜原因(「点太快了」)之前,先做实验把可能性排除;一张截图比十次猜测有用。

## 没验证的
- 「库存被买光」在真机上跳过——测试程序在手机上访问不到 Mac 的管理 API(没有本地网络权限),是测试环境的限制。
- 「服务器挂掉再恢复」只在模拟器上跑过。
