## 1. struct 是什么

**struct（構造体 / こうぞうたい / structure）** 把几样数据打包成一个新类型，很像 Python 的 `@dataclass`：

```python
# Python
@dataclass
class Product:
    id: int
    name: str
    price: int
    stock: int
```

```swift
// Swift
struct Product {
    let id: Int
    let name: String
    let price: Int
    var stock: Int
}
let shirt = Product(id: 1, name: "T恤", price: 3000, stock: 5)
```

### 1.1 几个名词

| 中文 | 日语 | 英文 | 例子 |
|---|---|---|---|
| 属性 | プロパティ | property | `id`、`stock` |
| 实例 | インスタンス | instance | `shirt` |
| 方法 | メソッド | method | `func label()` |
| 计算属性 | 計算プロパティ（けいさんプロパティ） | computed property | `var isSoldOut: Bool { stock == 0 }` |
| 成员初始化器 | メンバーワイズイニシャライザ | memberwise initializer | Swift 自动生成的 `Product(id:name:price:stock:)` |

### 1.2 自动生成的初始化器

你**没写** `init`，Swift 也帮你生成了一个。规则：

- 参数顺序 = 属性的声明顺序
- 必须写参数名（`id:`、`name:`……）

顺序写错会报（实测）：

```text
error: argument 'id' must precede argument 'name'
```

## 2. 计算属性和方法

上一步的 `Product` 只能装数据。这一步让它自己会「算」。

**计算属性**：

```swift
var isSoldOut: Bool {
    stock == 0
}
```

不存数据，每次读取时现算。相当于 Python 的 `@property`。用的时候不加括号：`shirt.isSoldOut`。

**方法（メソッド / method）** 就是写在 struct 里面的函数，里面可以直接用 `name`、`stock` 这些属性：

```swift
func label() -> String {
    if isSoldOut { return "\(name)（售罄）" }
    return "\(name) 剩 \(stock) 件"
}
```

读计算属性**不加括号**（`shirt.isSoldOut`），调用方法**要加括号**（`shirt.label()`）。

## 3. `let` / `var` 的两层含义

对 struct 来说，`let` 出现在两个地方，各管一层：

|  | 属性是 `let`（`name`） | 属性是 `var`（`stock`） |
|---|---|---|
| 实例是 `let`（`let shirt`） | ❌ | ❌ |
| 实例是 `var`（`var a`） | ❌ | ✅ |

**只有「var 实例 + var 属性」才能改。**

为什么 `let` 实例连 `var` 属性都不能改？因为 struct 是一个「值」——改它的一个字段，就等于把整个值换掉了。`let` 的值不允许变。

实测报错：

```text
shirt.stock = 4   → error: cannot assign to property: 'shirt' is a 'let' constant
a.name = "帽子"    → error: cannot assign to property: 'name' is a 'let' constant
```

注意看报错里**是谁**是 `'let' constant`：第一个是实例 `shirt`，第二个是属性 `name`。读报错时分清这一点，就知道该改哪里。

项目里的 `Product`（`ai-live-commerce-ios/AILiveCommerce/Models.swift`）就是这样设计的：**只有 `stock` 是 `var`**，其他全是 `let`。因为直播中只有库存会变，商品名、价格不会在 App 里被改。

## 4. `mutating`：会修改自己的方法

```swift
struct Product {
    var stock: Int
    mutating func sell(_ count: Int) {
        stock -= count
    }
}
```

struct 的方法里，`self` 默认是**只读**的。想在方法里改属性，必须写 `mutating`（ミューテイティング），意思是「调用这个方法会改变这个值」。

不写的话（实测）：

```text
error: left side of mutating operator isn't mutable: 'self' is immutable
```

对 `let` 实例调用 `mutating` 方法（实测）：

```text
error: cannot use mutating member on immutable value: 'shirt' is a 'let' constant
```

这两条是一回事：`let` 的值不能变，而 `mutating` 方法会改变值。

> class 的方法不需要（也不能）写 `mutating`——第 8 节会说为什么。

## 5. 值语义：今天最重要的一节

**值类型（値型 / あたいがた / value type）**：赋值的时候，**整个复制一份**。

```swift
var a = Product(id: 1, name: "T恤", price: 3000, stock: 5)
var b = a          // 复制！
b.stock = 0
print(a.stock)     // 5   ← a 没变
```

同样的事在 Python 里：

```python
a = Product(1, "T恤", 3000, 5)
b = a              # 不复制，b 和 a 是同一个对象的两个名字
b.stock = 0
print(a.stock)     # 0   ← a 也变了
```

用图来想：

```text
Swift struct（值）              Python 对象 / Swift class（引用）
┌───────────┐ ┌───────────┐     a ──┐
│ a: stock 5│ │ b: stock 0│         ├──▶ ┌──────────┐
└───────────┘ └───────────┘     b ──┘    │ stock: 0 │
  两个独立的盒子                          └──────────┘
                                          一个盒子，两张标签
```

**为什么 Swift 要这样设计？** 你把一个 struct 传给别的函数、存进别的变量，**不用担心别人偷偷改掉你手上那份**。在 App 里，很多地方同时用着同一份数据（画面、网络、缓存），值语义能少掉一大类「不知道谁改了它」的 bug。

## 6. 数组里的 struct：`for-in` 拿到的是副本

这是第 5 节的直接后果，也是今天和项目代码联系最紧的一节。

```swift
var products = [Product(...), Product(...)]

// ❌ 编译不过：p 是 let
for p in products { p.stock = 0 }
// error: cannot assign to property: 'p' is a 'let' constant

// ❌ 编译通过，但没用：p 是副本，改完就扔了
for var p in products { p.stock = 0 }

// ✅ 用下标直接改数组里的元素
for i in products.indices { products[i].stock = 0 }
```

Python 里 `for p in products: p.stock = 0` 是能生效的（因为 `p` 引用的就是列表里那个对象）。**这是从 Python 转过来最常犯的错。**

### 项目里的真实代码

`ai-live-commerce-ios/AILiveCommerce/AppState.swift`，直播中收到「有人买了东西」的消息时：

```swift
case .purchase(let nick, let items, let stocks):
    ...
    for i in products.indices {
        if let s = stocks[String(products[i].id)] { products[i].stock = s }
    }
```

逐个拆开：

| 代码 | 意思 | 哪天学的 |
|---|---|---|
| `stocks` | 服务器发来的 `[String: Int]`，比如 `["1": 3]` | 第 1 天 字典 |
| `String(products[i].id)` | 字典的 key 是字符串，所以把 `Int` 的 id 转成 `String` | 第 1 天 类型转换 |
| `stocks[...]` | 取值是 `Int?`，这个商品可能不在字典里 | 第 2 天 |
| `if let s = ...` | 有新库存才更新 | 第 2 天 |
| `for i in products.indices` + `products[i].stock = s` | 用下标改数组里的那个，而不是副本 | **今天** |

## 7. 函数参数也是副本（顺带一提）

```swift
func clearStock(_ p: Product) -> Product {
    var copy = p        // 参数 p 是 let
    copy.stock = 0
    return copy
}
```

传进函数的 struct 是一份副本，而且是 `let`。想让函数直接改调用方的变量，要用 `inout` + `&`（了解即可）。实际开发里更常见的是「返回一个新值」这种写法。

## 8. 对照组：class 是引用

**class（クラス）** 是**引用类型（参照型 / さんしょうがた / reference type）**，行为和 Python 一样：

```swift
class ProductRef {
    var stock: Int
    init(stock: Int) { self.stock = stock }   // class 必须自己写 init
}
let r1 = ProductRef(stock: 5)
let r2 = r1          // 不复制，指向同一个对象
r2.stock = 0
print(r1.stock)      // 0
print(r1 === r2)     // true，=== 判断是不是同一个对象（≈ Python 的 is）
```

### struct 和 class 的区别一览

|  | struct | class |
|---|---|---|
| 类型 | 值类型（値型） | 引用类型（参照型） |
| 赋值时 | 复制 | 共享同一个对象 |
| 自动初始化器 | ✅ 有 | ❌ 没有，要自己写 `init`（不写报 `class 'R' has no initializers`） |
| `let` 实例能改 `var` 属性吗 | ❌ | ✅（`let` 只锁住「指向哪个对象」） |
| 修改自己的方法 | 要写 `mutating` | 不用写 |
| 继承（継承 / けいしょう / inheritance） | ❌ | ✅ |

最容易糊涂的一行：class 的 `let r2` 为什么能改 `r2.stock`？

- `r2.stock = 0` → 改的是**对象的内容**，`r2` 还指着同一个对象 → ✅
- `r2 = ProductRef(...)` → 让 `r2` **指向另一个对象** → ❌ `cannot assign to value: 'r2' is a 'let' constant`

### 项目里怎么选的？

看一眼项目里所有的类型声明：

```text
struct Product, CartItem, Order, ChatLine ...   ← 数据：全是 struct
struct LiveView, ProductsView, LoginView ...    ← 画面（SwiftUI 的 View）：全是 struct
final class AppState                            ← 整个 App 共享的状态：class
final class APIClient, LiveSocket               ← 网络连接：class
```

规律：

- **数据和画面用 struct**。Swift 官方推荐「默认用 struct」。
- **需要「大家共享同一个」的东西用 class**。比如 `AppState`：直播画面和商品画面要看到**同一份**状态，一边改了另一边要立刻知道。如果是 struct，每个画面拿到的都是各自的副本，就对不上了。

> 🗣 日语面试表达：
> 「基本的には struct を使い、状態を複数の画面で共有したい場合は class を使います。」
> （基本上用 struct；需要在多个画面之间共享状态时用 class。）

<details>
<summary>参考答案（自己写完再看；已在 Swift 6.4 上实际运行过）</summary>

```swift
struct CartItem {
    let product: Product
    var quantity: Int
    var subtotal: Int { product.price * quantity }
}

struct Cart {
    var items: [CartItem] = []

    var total: Int {
        var sum = 0
        for item in items { sum += item.subtotal }
        return sum
    }

    mutating func add(_ product: Product, quantity: Int) {
        for i in items.indices {
            if items[i].product.id == product.id {
                items[i].quantity += quantity
                return
            }
        }
        items.append(CartItem(product: product, quantity: quantity))
    }

    mutating func remove(id: Int) {
        items.removeAll { $0.product.id == id }
    }
}
```
</details>
